LINE構築 MVP設計

初期構築・データ蓄積基盤の整備

クライアント: MEGA柴 / 2026.05 / v1.0
01

構築目的

現在の課題は「認知拡大に思考が偏っている」こと。サイト売上が伸び悩み、新規獲得への目線が強くなっている。本来の打ち手はデータドリブン運用の実現。LINE構築の役割は、その初期データアセットを整える「器」を作ること。配信・販促・施策連動はすべて後フェーズ。
目的 01

顧客識別の起点

サイト会員とLINE友だちを擬似的に紐付け、後続の分析・配信のIDキーを確保する。

目的 02

属性・行動データ取得

登録有無・認知経路・年代を起点に、施策ROIを評価できるセグメント基盤を作る。

目的 03

仮説検証サイクル開始

蓄積したデータから課題を抽出し、打ち手を選定する運用サイクルを立ち上げる。

MVPスコープ

含めるもの

ID連携基盤 / 最小タグ設計 / 入口別フック設計 / 共通アンケートフォーム / 週次データ突合運用

含めないもの

リッチメニュー作り込み / 複雑なシナリオ配信 / セグメント別パーソナライズ配信 / AIチャットボット / 認知拡大施策との連動

共通アンケートフォーム

入口は分かれても、聞くことは同じ。3問×低負荷で離脱を抑えながら、後の分析の核となる軸を確保する。

Q1 / 分岐の起点

サイト登録の有無

  • 登録済み（→メアド入力へ）
  • 未登録
  • 登録済みかわからない
Q2 / 認知計測

サイトを知ったきっかけ

  • 広告
  • SNS（X・Instagram等）
  • ライブ配信
  • 友人紹介 / 検索 / その他
Q3 / 属性把握

年代

  • 10代 / 20代 / 30代
  • 40代 / 50代以上
IF 入口_新規 OR 未登録
→ ビンゴカード画像を送信
アンケート完了タグ + ビンゴ参加タグを自動付与
IF 入口_既存 OR 登録済み
→ クーポンコードを送信
アンケート完了タグ + クーポン受領タグを自動付与
03

タグ設計

タグは「軸」として設計する。流入と認知を分離し、属性と行動を分離する。これにより後の運用で「広告流入 × 20代 × 未登録 × 完了」のような多軸クロス分析が可能になる。
軸 01

入口セグメント

入口_新規あいさつ経由 入口_既存配信経由
軸 02

サイト登録状況

登録済み_メアド取得済 未登録 登録状況不明
軸 03

流入経路（URLパラメータ）

流入_広告 流入_ライブ配信 流入_サイト 流入_SNS 流入_その他
軸 04

認知経路（Q2回答）

認知_広告 認知_SNS 認知_ライブ配信 認知_紹介 認知_検索 認知_その他
軸 05

年代（Q3回答）

年代_10代 年代_20代 年代_30代 年代_40代 年代_50代以上
軸 06

進捗・フック受領状況

アンケート完了 アンケート未完了 ビンゴ参加 クーポン受領

05

制約と運用前提

レンタルカートのためサイトDBとエルステの自動連携は組めない。これを前提に、データ突合は週次CSV運用で擬似連携する。初回配信は精度を捨て、2回目以降のセグメント精度向上に賭ける。
前提 01

システム連携不可

リアルタイム連携は諦め、メアドを突合キーとした週次CSVマッチング運用で代替する。

前提 02

クーポン手動運用

コードは事前大量発行（100〜500件）。配布は自動、サイト側使用状況の確認は週次バッチ。

前提 03

初回配信は精度なし

既存セグメント精度は初回ゼロ。回答が貯まる2回目以降から本領発揮する設計。
